## 1. 결론

**현재 상태에서 곧바로 재심사를 요청하는 것은 권하지 않습니다.** 페이지 접근성과 다국어 URL 구조는 양호하지만, 실제 결과가 틀리는 계산 기능, 데이터 출처와 설명의 불일치, 반복적인 안내 문구가 남아 있습니다. 글자 수나 디자인을 더하는 것보다 이러한 문제를 먼저 해결해야 합니다.

세 차례의 동일한 거절 사유는 사용자가 제공한 정보입니다. Google은 문제 URL과 내부 평가 내역을 공개하지 않았으므로, 아래 결함이 거절의 직접 원인이라고 확정할 수는 없습니다. 승인 확률이나 승인 보장도 제시하지 않습니다.

Google은 고유하고 유용한 콘텐츠를 요구하며 사이트의 여러 페이지를 검토할 수 있다고 안내합니다. 모든 도구에 1,000~1,500자를 넣어야 한다는 공식 최소 분량은 이 안내에 없습니다. [AdSense 승인 문제 해결 안내](https://support.google.com/adsense/answer/81904?hl=ko)

이번 작업은 검토입니다. 애플리케이션 코드 수정, 배포, GitHub 반영, 재심사 신청은 하지 않았습니다.

## 3. 우선 수정할 확인된 문제

우선순위는 Google의 등급이 아니라 이 검토의 작업 순서입니다. P1은 결과 정확성·신뢰성 또는 수익화 전 이용 조건, P2는 설명·사용성·콘텐츠 개선을 의미합니다.

### P1-1. 단위·픽셀 변환기가 정수의 0을 삭제함

- 운영 재현: 단위 변환 `1 m → cm`, 소수 자릿수 `0`에서 결과 `1`. 올바른 값은 `100`입니다.
- 운영 재현: 픽셀 변환 `160 px → rem`, 기준 `16 px`, 소수 자릿수 `0`에서 결과 `1`. 올바른 값은 `10`입니다.
- 원인: `toFixed(precision).replace(/\.?0+$/, "")`가 소수점 아래 0뿐 아니라 정수 끝자리의 0도 지웁니다. 결과 0도 빈 문자열이 될 수 있습니다.
- 근거: `src/features/tools/implementations/unit-converter.tsx:157`, `src/features/tools/implementations/pixel-converter.tsx:54`.
- 조치: 소수 부분에만 0 제거 적용. 0·10·100·음수·소수 자릿수 0을 회귀 테스트에 추가합니다. 전체 언어가 같은 구현을 사용합니다.

### P1-2. 환율 변환기의 현지 숫자 해석 오류

- 운영 재현: 프랑스어 페이지에서 `1,5` USD 입력 시 `15` USD로 계산합니다. 확인 시점 환율 0.85947에서 표시값은 `12,89 EUR`; 의도한 1.5 USD는 약 `1,29 EUR`입니다.
- 원인: 언어와 관계없이 모든 쉼표를 제거합니다. `1 000,50` 같은 입력은 유효하지 않은 값이 된 뒤 0으로 처리될 수 있습니다.
- 근거: `src/features/tools/implementations/currency-converter.tsx:209`.
- 조치: 소수점·그룹 구분자를 언어별로 해석하고 불명확한 입력은 오류로 안내합니다. 잘못된 입력을 0으로 바꾸지 않습니다.
- 추가: `src/app/api/exchange-rates/route.ts:81`은 첫 행의 날짜를 전체 기준일로 사용합니다. 원본 응답에서 통화쌍마다 서로 다른 날짜가 실제 확인됐으므로 날짜를 통화쌍별로 보존해야 합니다. 캐시 시점 차이를 환율 오류로 판단하지는 않았습니다.

### P1-3. 연봉 계산기의 세금 추정 방식과 공식 예시 사이 큰 차이

- 운영 재현: 연봉 42,000,000원, 상세 입력, 비과세 0원, 공제대상 가족 4명, 해당 자녀 2명, 퇴직금 별도. 소득세 표시 `120,449원`.
- 국세청 공개 예시: 월급 3,500,000원, 가족 4명, 해당 자녀 2명의 원천징수 소득세 `20,180원`. 같은 조건으로 비교했을 때 소득세만 100,269원 차이입니다. [국세청 간이세액표 예시](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7862&mi=6583)
- 원인: 연간 과세표준으로 산출한 세액을 12로 나누고 월별 자녀 조정액을 빼는 혼합 추정식입니다. 근로소득세액공제가 계산에 반영되지 않습니다. [국세청 근로소득세액공제 설명](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7875&mi=6596)
- 근거: `src/features/tools/implementations/salary-calculator.tsx:79`, `src/features/tools/implementations/salary-calculator.tsx:91`.
- 추정치라는 안내는 이미 있습니다. 그러나 안내만으로 큰 편차를 해결할 수는 없습니다. 공식 간이세액표 기반의 월 원천징수 추정으로 정리하고 표의 경계값·가족·자녀 조건을 검증하는 것이 우선입니다.
- 현재 보험료율과 국민연금 상·하한을 무조건 낡았다고 판단하지 않았습니다. 2026년 공표 기준과 대조했습니다. 국민연금 기준소득월액의 천 원 미만 처리 등 세부 산식은 별도 보강해야 합니다. [국민연금 기준](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0097M0.do), [건강보험 2026년 안내](https://edi.nhis.or.kr/portal/images/popup/20251204_pop01longdesc.html)

### P1-4. 퍼센트 계산기가 정의할 수 없는 증가율을 0%로 표시

- 운영 재현: 증가율 모드, 기준값 `0`, 비교값 `100`에서 `0.00% 증가했습니다.` 표시.
- 0을 기준으로 한 상대 증가율은 이 수식으로 계산할 수 없습니다. 0% 변화와는 다른 상태입니다.
- 근거: `src/features/tools/implementations/percentage-calculator.tsx:96`.
- 조치: 증가율·감소율에서 분모 0을 별도로 안내하고 결과를 표시하지 않습니다. 일반 비율 계산의 0과 구분합니다.

### P1-5. 외출 건강 지표의 데이터 성격과 표시가 어긋남

- Open-Meteo의 모델 기반 대기질·예보값을 사용하면서 화면에는 `실시간 지표 대시보드`라고 표시합니다. 인근 관측소의 실측값으로 오해할 수 있습니다.
- API `current.time`은 값의 유효 시각이지 모델이 갱신된 시각을 보장하는 필드가 아닙니다. 이를 `sourceUpdatedAt`으로 부릅니다.
- 시간대 없는 문자열을 `new Date()`로 해석합니다. UTC 환경에서 한국 시각 `2026-09-10T02:00`을 입력하면 화면용 한국 시간은 11:00이 됩니다. 한국 시간대 브라우저에서는 드러나지 않는 문제입니다.
- 지역은 광역지역 전체 집계가 아닌 대표 좌표 한 곳입니다. 지역 범위와 실제 데이터 해상도를 구분해야 합니다.
- `AirKorea 통합대기환경지수`를 참고 기준으로 표시하지만 공식 CAI 산식 전체를 구현한 것은 아닙니다. 자체 단계와 공식 지수를 명확히 구분해야 합니다. [AirKorea CAI 설명](https://m.airkorea.or.kr/info/cai)
- 현재 페이지는 위치 변경 때 조회하고, 열린 페이지에서 자동 재조회하지 않습니다. 값의 경과 시간과 오래된 데이터 상태도 필요합니다.
- 근거: `src/app/api/outdoor-health/route.ts:85`, `src/features/tools/implementations/outdoor-health-index.tsx:152`, `src/features/tools/implementations/outdoor-health-index.tsx:200`, `src/features/tools/implementations/outdoor-health-index.tsx:396`.
- 조치: `모델 예보 기반 참고 정보`로 표시하고 유효 시각·조회 시각을 분리합니다. 시간대를 보존하고 일부 누락·지연 때 종합 결과의 한계를 함께 표시합니다. 외출 안전을 보장하는 문구는 사용하지 않습니다.

### P1-6. 한국 꽃가루와 광고 수익화 시 API 이용 조건

- 공식 API 문서에서 꽃가루 제공 범위는 유럽입니다. 한국어 전용 도구의 한국 지역에서 5개 꽃가루 값이 모두 null인 운영 응답을 확인했습니다. 단순한 일시 오류로 취급하면 안 됩니다.
- 현재 `제공되지 않을 수 있습니다`보다 `이 제공원은 한국 꽃가루를 지원하지 않습니다`가 정확합니다. 다른 제공원 연결 전까지 명확한 미지원 상태가 필요합니다.
- 자체 꽃가루 단계의 경계 0·20·100에 대한 종별·공식 기준 근거가 제시되지 않습니다. 기상청 링크를 달았다는 이유로 기상청 지수와 동일하다고 볼 수 없습니다.
- Open-Meteo 문서는 CAMS와 Open-Meteo 출처 표시를 요구합니다. 현재 화면에는 CAMS 표시가 빠져 있습니다. [공식 대기질 API 문서](https://open-meteo.com/en/docs/air-quality-api)
- 무료 API는 비상업용이며 광고를 게재하는 웹사이트는 상업적 사용 예시에 해당합니다. 광고 수익화 전에 적합한 구독 또는 상업 이용 가능한 대체 제공원을 확보해야 합니다. 현재 광고가 꺼진 상태에서 이미 계약 위반이라고 단정하지는 않습니다. [Open-Meteo 이용 조건](https://open-meteo.com/en/terms)
- 근거: `src/app/api/outdoor-health/route.ts:24`, `src/features/tools/implementations/outdoor-health-index.tsx:144`, `src/features/tools/implementations/outdoor-health-index.tsx:248`.

### P1-7. 텍스트 비교기가 삽입과 삭제를 정렬하지 않음

- 원인: 같은 행 번호끼리 비교할 뿐 삽입·삭제 이후의 동일 줄을 정렬하지 않습니다.

## 4. 콘텐츠와 다국어 품질

### 실질적인 추가 가치가 부족한 부분

- 보강된 5개 핵심 도구는 구현에 맞는 예시·한계·출처가 있습니다. 나머지 도구까지 같은 수준의 검증이 완료된 상태는 아닙니다.
- 카테고리의 `작업 흐름`은 실제 순서나 결과 해석보다 도구의 짧은 설명을 다시 조합한 문장에 가깝습니다. 카드·선택 안내·작업 흐름에 유사 문장이 반복됩니다.
- 한국어 운영 페이지에서 `배경 제거기을`, `외출 건강 지수을` 같은 어색한 조사가 확인됩니다. 원인은 `src/components/category-hub-page.tsx:63`의 공통 문장 템플릿입니다.
- 홈의 일반적인 편리함·속도·다국어 홍보를 더 늘리는 것보다 실제 문제 해결 사례를 연결하는 편이 유용합니다. 카테고리도 도구 목록 반복 대신 선택 기준과 함께 사용하는 순서를 제시해야 합니다.
- 이것을 Google이 거절한 정확한 원인이라고 단정하지 않습니다. 편집 품질 및 고유한 정보 가치에 대한 검토 판단입니다.

### 누락과 오역을 분리해야 함

- 지원 언어별 도구 사전 항목과 장문 설명·사용법·FAQ 구조의 누락은 이번 검사에서 없었습니다.
- 그러나 QR의 빈 상태가 한국어에서도 영어이고, 색상 변환의 입력 라벨·복사·초기화·오류가 영어입니다. 텍스트 비교에는 `Edit Texts`, 수정문 제목에는 다른 도구의 `단위 변경` 번역 키가 쓰입니다.
- 서버의 바코드 생성 오류는 다른 언어 페이지에도 한국어로 전달됩니다.
- 이 때문에 `번역 파일이 존재한다`와 `전체 UI가 현지화됐다`는 별개입니다. 빈 상태·정상 결과·잘못된 입력·API 실패를 언어별로 검사해야 합니다.
- 번역은 정확한 원문과 기능을 확정한 뒤 반영해야 합니다. 부정확한 주장을 10개 언어로 반복하지 않아야 합니다.

## 5. 개인정보·광고·운영 신뢰

1. **QR·바코드 입력은 서버로 전송됩니다.** 입력 후 400ms가 지나면 `/api/generate-barcode?text=...`에 원문을 보냅니다. 개인정보처리방침의 외부 조회 설명만으로는 이 처리를 충분히 설명하지 못합니다. 서버 처리와 입력 내용, 목적, 실제 보관 정책을 명시하고 가능하면 클라이언트 생성 또는 POST 등으로 URL 노출을 줄여야 합니다. URL이 실제로 얼마나 기록되는지는 호스팅 로그 설정 확인이 필요합니다. 근거: `src/features/tools/implementations/barcode-generator.tsx:134`.
2. **전광판은 문구 자체를 localStorage에 저장합니다.** 일반 환경설정뿐 아니라 입력 문구가 이 기기에 남는다는 안내와 초기화 시 삭제 범위를 검토해야 합니다. 근거: `src/features/tools/implementations/signboard.tsx:99`.
3. **개인정보처리방침에 Google 광고·쿠키·광고 설정 링크는 이미 있습니다.** 단순히 DART라는 단어를 추가하는 것이 해결책은 아닙니다. 실제 처리와 문구가 일치해야 합니다.
4. **문의 메일과 DNS MX는 존재합니다.** 실제 발송·수신 시험은 하지 않았으므로 문의 창구 정상 수신을 인증하지 않습니다. 운영자가 수신 확인을 해야 합니다.
5. **소개 페이지는 일반 서비스 소개 중심입니다.** 누가 어떤 기준으로 도구를 검증하는지, 변경·검토 이력을 어떻게 관리하는지 실제 운영 사실을 추가하면 좋습니다. 가짜 경력·가짜 시험 결과·임의의 검토일은 추가하면 안 됩니다.
6. **광고 로딩은 기본 비활성이고 5개 도구로 제한하는 코드가 있습니다.** 이는 긍정적이나 사이트 전체 편집 품질이나 향후 동의 의무를 대체하지 않습니다. 화면을 밝히기만 하는 도구 등은 낮은 가치의 광고 지면이 될 위험이 있어 현재 제한을 유지하는 편이 타당합니다. [Google의 콘텐츠 없는 화면·낮은 가치 콘텐츠 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=ko)

## 7. 모바일·접근성·성능의 남은 확인

- 이번 390px 기본 화면 검사는 루트 넘침이 없다는 결과입니다. 모든 내부 스크롤, 모달, 키보드, 장문 결과까지 문제가 없다는 뜻은 아닙니다.
- 디지털 시계 색상 프리셋 버튼에 접근 가능한 이름이 없습니다. 접근성 스냅샷에서도 이름 없는 버튼으로 확인됩니다. `src/features/tools/implementations/digitalclock.tsx:233`에 색상명·선택 상태를 제공해야 합니다.
- 이미지 압축은 파일 수·픽셀 수 제한, 배경 제거는 초기 모델 다운로드·저사양 기기·취소 시 처리 종료가 추가 점검 대상입니다. 이번 배경 제거 완료는 다양한 이미지의 분리 품질 검증을 대신하지 않습니다.
- 타이머의 전면 탭 완료는 백그라운드 정확도와 소리 재생을 보장하지 않습니다. 브라우저는 비활성 탭 타이머를 제한하고 자동 오디오를 차단할 수 있습니다. [MDN 타이머 제한](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout#timeouts_in_inactive_tabs), [MDN 자동 재생](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)
- 실제 Core Web Vitals 필드 데이터, 저속망 장기 테스트, 스크린리더 전체 흐름, 침투 테스트는 이번 검토 범위에 포함되지 않았습니다.
