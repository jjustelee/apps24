# Apps24 AdSense 심사 관점 분석과 대안

검토일: 2026-10-07. 운영 사이트 https://www.apps24.io 와 로컬 프로젝트를 대조했다. 로컬 기준 커밋은 `fe2f727`이며 2026-09-10 검토 이후 애플리케이션 코드 변경은 확인되지 않았다.

## 판단

지금 재심사를 반복하기보다 실제 도구 오류를 수정하고, 도구별 고유한 문제 해결 정보를 보강하는 것이 우선이다. 기본적인 웹 접근과 메타데이터는 양호하다. 반면 콘텐츠의 반복, 안내와 실제 동작의 차이, 일부 결과 오류가 남아 있다.

이것이 Google 내부 평가에서 거절을 일으킨 정확한 원인이라는 뜻은 아니다. 이전에 제공된 거절 사유는 '가치 없는 콘텐츠'였지만 문제 URL이나 평가 내역은 공개되지 않았다. 승인 확률이나 승인 보장은 산출할 수 없다.

Google은 고유하고 유용한 콘텐츠, 명확한 탐색, 만족스러운 사용 경험을 요구한다. 광고 코드가 있는 URL 외에 사이트의 모든 페이지도 검토될 수 있다. [사이트 준비도 안내](https://support.google.com/adsense/answer/7299563?hl=ko), [승인 문제 해결 안내](https://support.google.com/adsense/answer/81904?hl=ko)

## 현재 확인한 사실

| 범위 | 결과 | 의미 |
| --- | --- | --- |
| 사이트맵 URL 333개 | 모두 HTTP 200, 자기 canonical, H1 1개, noindex 없음 | 접근·기본 색인 설정 문제를 우선 원인으로 보기 어려움 |
| hreflang 3,636개 | 연결 대상과 자기 참조 정상 | 다국어 URL 연결은 양호; 번역 품질은 별도 |
| 초기 HTML | 실제 본문·탐색 링크 존재 | 빈 CSR 화면을 이유로 SSR 전환할 필요는 확인되지 않음 |
| 초기 HTML 광고 스크립트 | 333개에서 미검출 | 현재 광고 배치 개선이 저가치 콘텐츠 문제를 해결하지는 않음 |
| 프로젝트 도구 | 24개, 언어별 도구 URL 222개 | 글로벌 22개, 한국어 전용 2개 |
| 구현에 맞게 별도 검수한 콘텐츠 모듈 | 자·글자 수·JSON·이미지 압축·IP 조회 5개 | 나머지에도 같은 수준의 예시·제한·오류 설명 점검 필요 |

사이트맵 밖 전체 URL, Search Console 내부 색인·트래픽, AdSense 계정 상태는 이번에 확인하지 않았다. HTTP 200과 index 허용은 Google에 실제 색인됐다는 증거가 아니다.

## 우선순위가 높은 문제

### 1. 도구가 제공하는 답변 자체의 정확성

이번 운영 브라우저에서 아래 오류를 다시 재현했다.

| 입력 | 현재 결과 | 기대 결과 | 코드 근거 |
| --- | --- | --- | --- |
| 1m → cm, 소수 자릿수 0 | 1 | 100 | `src/features/tools/implementations/unit-converter.tsx:157` |
| 프랑스어 환율 입력 1,5 USD | 15 USD로 계산하여 13,34 EUR 표시 | 1.5 USD, 당시 환율로 약 1,33 EUR | `src/features/tools/implementations/currency-converter.tsx:209` |
| A/B/C 앞에 X 한 줄 추가 | 기존 세 줄 변경, C 추가 | X만 추가, A/B/C는 일치 | `src/features/tools/implementations/text-diff-checker.tsx:25` |

이전 보고서의 픽셀·퍼센트·연봉 계산 문제와 관련된 구현도 변경되지 않았다. 이번에는 해당 사례 전체를 다시 조작하거나 세금 공식 자료 전체를 새로 검증하지 않았다. 상세 재현 기록은 `docs/deep-review-2026-09-10.md`에 있다.

계산기의 정확성은 그 페이지의 정보 가치다. 오류 수정과 기대값 테스트 없이 설명 글만 더하면 부정확한 결과의 근거를 늘릴 수 있다. 먼저 실제 입력과 기대값이 일치하도록 수정해야 한다.

### 2. 읽을 내용은 있지만 결과를 이해하게 하는 정보가 부족함

QR 페이지에는 활용처, 일반적인 사용 방법, 사용하는 이유, FAQ가 있다. 그러나 메뉴·포스터·패키징 등의 활용처가 여러 섹션에서 반복된다. WiFi·vCard 입력의 실제 형식, 출력 예, 스캔 실패 확인법 등 사용자의 구체적인 질문에 답하는 정보가 상대적으로 부족하다.

텍스트 비교기에는 '정확한 차이', '상세한 비교 분석'이라는 안내가 있으나 행 번호끼리만 비교한다. 안내와 구현을 함께 고쳐야 한다.

카테고리의 '작업 흐름'은 기존 도구 설명을 다시 붙인 문장이다. 운영 생성 카테고리에는 'QR 코드 생성기을 사용할 수 있습니다'라는 어색한 문장도 있다. 근거: `src/components/category-hub-page.tsx:302`.

이는 편집 품질에 관한 검토 판단이다. 글자 수만으로 저가치 콘텐츠 여부를 판정하거나 모든 템플릿을 정책 위반으로 간주하지 않는다.

### 3. 민감한 도구의 출처와 범위

외출 건강 지표는 모델 예보를 사용하지만 '실시간 지표 대시보드'로 표시한다. 값의 유효 시각과 제공원이 갱신한 시각도 구분해야 한다. 근거: `src/features/tools/implementations/outdoor-health-index.tsx:396`, `src/app/api/outdoor-health/route.ts:85`.

Open-Meteo는 꽃가루를 유럽에만 제공한다고 명시한다. 한국어 전용 페이지의 한국 꽃가루는 일시 장애처럼 설명하지 말고 제공원 미지원으로 안내해야 한다. [공식 대기질 API 문서](https://open-meteo.com/en/docs/air-quality-api)

무료 API의 이용 조건은 비상업용이며 광고를 표시하는 웹사이트를 상업적 사용 예로 든다. 수익화 전에 적합한 구독이나 다른 제공원을 마련해야 한다. 이것을 현재 AdSense 거절 원인으로 단정하지 않는다. [Open-Meteo 이용 조건](https://open-meteo.com/en/terms)

### 4. 다국어 완성도와 운영 사실

한국어 단위 변환 UI에는 INPUT SOURCE, CONVERTED RESULT, Time 등의 영어가 남아 있고 QR 빈 상태도 영어다. 파일이 번역돼 있어도 성공·실패·빈 상태까지 번역이 완료됐다고 볼 수 없다.

소개 페이지는 제공 기능과 장점 중심이다. 실제 운영 주체, 도구 검증 방법, 오류 접수·수정 절차를 설명하면 신뢰에 도움이 된다. 작성자 실명이나 경력을 지어내거나 공통 날짜를 검수일처럼 붙이면 안 된다. 이런 정보가 각각 독립적인 승인 필수 조건이라고 주장하지는 않는다.

QR·바코드 원문은 서버에 URL 쿼리로 전송된다. 개인정보 안내에는 이 처리를 구체적으로 설명할 필요가 있다. 근거: `src/features/tools/implementations/barcode-generator.tsx:134`. 실제 요청 로그 보관 기간은 호스팅 설정 확인이 필요하다.

Google 광고 쿠키와 개인 맞춤 광고 설정 링크는 이미 개인정보처리방침에 있다. 이를 다시 작성하는 것만으로 고유 콘텐츠 문제를 해결할 수는 없다. [Google 개인정보 안내 요구사항](https://support.google.com/adsense/answer/1348695?hl=ko)

## 선택 가능한 대안

| 대안 | 적용 방식 | 평가 |
| --- | --- | --- |
| A. 기존 도구 페이지 집중 보강 | 기능 오류 수정, 각 페이지에 검증 예시·입력 제한·문제 해결 추가 | 변경 부담이 작지만 사이트 전체의 고유한 편집 콘텐츠가 여전히 약할 수 있음 |
| B. 도구와 직접 검증한 가이드 연결 | A를 진행하면서 핵심 작업에 대한 비교·실험·해설 글을 별도 제공 | 추천. 도구의 실용성과 읽을 콘텐츠의 가치를 함께 높일 수 있음 |
| C. 주력 분야 중심으로 홈 구성 | 검색 수요가 있는 측정·이미지·개발 도구를 중심에 배치, 나머지 URL 유지 | 방향성은 선명해지지만 이것만으로 승인 문제를 해결하지는 못함 |

추천은 B다. 주력 도구 선택에는 C의 기준을 사용할 수 있다. 기존 도구와 언어 URL을 유지하고 홈·도구 하단에 관련 가이드를 연결한다. 공통 FAQ를 늘리거나 검색 키워드별로 비슷한 페이지를 대량 생성하지 않는다.

## Apps24에 적합한 고유 콘텐츠 예시

아래 6개는 제안하는 첫 작업 묶음이며 Google이 요구하는 글 수가 아니다. 실제 시험 결과를 확보한 뒤 작성해야 한다.

| 가이드 주제 | 직접 확인하여 넣을 내용 | 연결 도구 |
| --- | --- | --- |
| 온라인 자가 실제 자와 다른 이유와 보정 방법 | 기준 카드 규격, 화면 확대·회전 영향, 실제 길이 비교 결과, 오차 | 온라인 자 |
| 같은 사진을 JPG·PNG·WebP로 저장했을 때 | 허가된 원본, 브라우저·설정, 출력 바이트 수·해상도, 화질 비교 이미지 | 이미지 압축 |
| PNG 품질을 낮춰도 용량이 줄지 않는 이유 | 현재 인코더의 실제 동작, 크기 축소와 WebP 선택의 비교 | 이미지 압축 |
| JSON의 큰 정수가 바뀌는 이유 | 9007199254740993 입력, 일반 숫자 변환과 현재 포맷 결과 비교, 문법·스키마 차이 | JSON |
| QR 코드가 스캔되지 않을 때 확인할 것 | 실제 URL 및 WiFi 입력 예, 인쇄 크기·여백·대비 시험, 실물 스캔 결과 | QR |
| 글자 수가 제출 사이트와 다른 이유 | 한글·줄바꿈·결합 문자·이모지의 계산 사례, 문자·바이트·UTF-16 구분 | 글자 수 |

이미지 크기·압축률·스캔 결과는 실제 값을 사용한다. 기존 글을 표현만 바꾸거나 자동 생성한 글을 검토 없이 게재하지 않는다. Google은 검토 없이 자동 생성한 콘텐츠와 가치가 낮은 화면의 광고 게재를 제한한다. [게시자 콘텐츠 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=ko)

가이드는 제목, 실제 문제, 시험 조건, 입력과 결과, 해석, 한계, 관련 도구, 출처 순으로 구성할 수 있다. 충분히 짧은 문제는 도구 하단에서 해결하고 독립적인 실험·비교가 있을 때 별도 가이드로 만든다. 내용이 겹치면 기존 페이지에 합친다.

## 실행 순서

1. 이전 보고서와 이번 재현에서 확인한 정확성 문제를 먼저 수정한다. 기대값·경계값 테스트로 검증한다.
2. 전체 공개 도구의 안내를 실제 기능과 맞춘다. 입력 형식, 서버 처리, 파일·데이터 제한, 실패 상태를 확인한다.
3. 주력 도구 5개에서 직접 검증한 사례와 가이드를 제작한다. 이전 제공된 Search Console 화면에는 온라인 자 관련 검색 수요가 있었으므로 자는 우선 후보지만 최신 데이터를 확인해 순서를 정한다.
4. 카테고리의 반복 설명을 도구 선택 기준으로 바꾸고 홈에서 도구와 관련 가이드를 찾기 쉽게 한다. 도구는 상단에서 계속 바로 사용할 수 있게 유지한다.
5. 원문을 검증한 뒤 언어별 사용 환경에 맞춰 번역한다. 기존 언어를 임의로 삭제하지 않고 빈 상태·결과·오류·숫자 입력까지 확인한다.
6. 운영 버전에 변경 내용이 반영됐는지 확인하고 페이지·문의 수신·모바일 사용을 다시 검사한다. 그 후 재심사 신청을 판단한다.

새 가이드 몇 편이 추가되더라도 다른 공개 페이지의 품질 문제는 남지 않아야 한다. 광고를 5개 도구로 제한한 구현은 전체 사이트 검토를 차단하지 못한다.

## 재심사 전에 확인할 완료 기준

- 알려진 계산·비교 오류의 재현 사례가 올바른 기대값으로 바뀐다.
- 공개 도구 페이지에 실제 입력·결과·해석 또는 필요한 작업 사례가 있고 안내와 기능이 일치한다.
- 카테고리·홈의 문장은 사용자의 선택을 돕고 동일 설명을 불필요하게 반복하지 않는다.
- 새 콘텐츠는 실제 시험·출처로 뒷받침되며 검토자가 설명할 수 있다.
- 지원 언어에서 주요 입력·오류 상태가 이해 가능하고 API의 지원 범위가 정확히 표시된다.
- 실제 운영 URL에서 접근·본문·메타데이터·모바일 결과가 확인된다.

이 기준은 Apps24의 작업 완료 기준이다. Google의 승인 체크리스트나 승인 보장 조건이 아니다. 공개 일반 자격 안내에는 특정 월 방문자 수나 모든 글의 최소 글자 수 기준이 제시돼 있지 않다. [일반 자격 요건](https://support.google.com/adsense/answer/9724?hl=ko)

언어 일괄 삭제, 승인만을 위한 대량 글 생성, 검토 직전에만 페이지 숨기기, 재신청 전 일정 일수 대기 등을 기본 해결책으로 권하지 않는다. 디지털 시계·스크린 라이트 같은 화면 목적의 도구는 별도로 광고 지면 적합성을 판단하고 기존 광고 제외 설정을 유지하는 편이 타당하다.

## 이번 검토의 산출물과 제한

- `output/playwright/adsense-oct-pages.json`: 운영 333개 URL의 상태·메타데이터·초기 본문.
